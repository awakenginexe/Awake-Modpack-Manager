# Awake Modpack Manager v0.2.0 (draft, unreleased)

Built on Awake Native Core 0.2.0 (protocol 2.0 + `manager.v0.2`), Awake Launcher `3b279ff06`.
See [INTEGRATION-020.md](../INTEGRATION-020.md) for pins, negotiation and the contract issues raised with Codex.

## New

* Projects with **Vanilla, Fabric, Forge, NeoForge and Quilt**: Minecraft and loader versions come from the
  helper's catalog; pairs without a loader build are explained instead of offered.
* **Install a modpack** (`.mrpack`, CurseForge ZIP) as a Manager project: the archive is uploaded to the
  helper in bounded chunks, checked, and every mod and override file is shown for review before anything
  is written. ZIP64/encrypted archives, non-Modrinth download hosts and CurseForge-hosted files are refused
  with an explanation, and nothing is changed.
* **Pins and update exclusions** stored in the project by the helper, as reviewed changes.
* **Export a project**: the Manager builds an `.mrpack` or CurseForge ZIP from the project's verified
  provider files; config files can be added from a pack archive (account, credential, log and save files
  are always left out). Files that can't be referenced are listed, never exported silently.
* Large plans (hundreds of mods or thousands of files) are shown in windowed lists.
* The installer refuses a substituted, corrupt, missing or extra helper file; so does the app before it
  starts the helper.

## Not available

* CurseForge search, downloads and CurseForge-hosted pack files: the helper ships without CurseForge API
  access (disabled until an approved arrangement exists).
* Exporting a project's own config files (the helper cannot read them out yet); add them from an archive.
* Playing: the Manager creates loader-ready projects but does not start Minecraft.
* Shared Awake Launcher instances stay read-only.

## Compatibility

* Projects and the project store from v0.1.0 open unchanged; an older 0.1.x helper is still understood
  (0.2 features are then hidden).
